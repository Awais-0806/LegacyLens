SSRF & Redirect Safety Review

File: backend/app/ingestion/fetcher.py  ·  Supporting: backend/app/services/url_validation.py  ·  Scope: Server-Side Request Forgery, open redirect, HTTP safety

Executive Summary

The fetcher was substantially hardened relative to its predecessor (fetcher.py.bak): it validates the input URL through validate_public_github_url before any network call is made, implements a controlled redirect-following loop that allowlists destination hosts, and enforces a download-size cap. The overall SSRF posture is good. However, four issues remain that range from medium to informational severity, and a gap in the upstream URL validator warrants attention.

What Is Working Well

Input validation first. Every caller goes through validate_public_github_url before the fetcher touches the network. The validator enforces HTTPS, blocks credentials/ports/query strings/fragments, pins the hostname to github.com, and rejects RFC-1918 / loopback IPs by name and by numeric value.
Redirect allowlist. _follow_redirects_to_zip turns off httpx's automatic redirect following and manually validates every Location header against a strict allowlist (github.com, codeload.github.com, objects.githubusercontent.com). This correctly prevents an attacker-controlled GitHub repository from redirecting the server to an internal endpoint.
Redirect cap. The loop iterates at most 5 times and raises on exhaustion, preventing infinite redirect chains.
Download size cap. A configurable max_bytes guard (default 100 MB) prevents memory exhaustion from a giant ZIP response.
Hardened versus the previous version. The backup (fetcher.py.bak) rejected all redirects blindly, which would block legitimate GitHub archive downloads. The current version replaces that naive approach with a targeted allowlist, which is the correct design.

Detailed Findings

F-01 Medium DNS Rebinding / TOCTOU on _resolve_default_branch
Description

_resolve_default_branch queries https://api.github.com/repos/{owner}/{repo} with follow_redirects=True and has no host-pinning on that call. The resolved branch name is then interpolated directly into the archive URL used in fetch(). There is a time-of-check / time-of-use gap: the validator has already approved the input URL, but this second outbound request is constructed internally and is not re-validated.

In the realistic threat model the attacker controls the GitHub repository and could manipulate API responses. More critically, if the GitHub API URL were ever parameterised or configurable in future, this path would have no SSRF guard.

Recommendation

Add explicit host pinning on the API request and strip follow_redirects:

r = httpx.get(
    api,
    timeout=min(self.timeout, 10),
    follow_redirects=False,          # GitHub API does not redirect
    headers={"Accept": "application/vnd.github+json"},
)
# Verify host before making the call (defensive):
assert urlparse(api).hostname == "api.github.com"
F-02 Medium Response body is buffered before the size check
Description

_follow_redirects_to_zip calls c.get(url, ...) which, by default in httpx, buffers the entire response body into memory before returning. The size check (len(r.content) > self.max_bytes) in fetch() happens after the full body has already been allocated. A malicious or misconfigured server in the allowlist could serve a multi-gigabyte response and cause OOM before the guard fires.

Recommendation

Use streaming and abort early on Content-Length or while reading chunks:

with httpx.stream("GET", url, headers={"Accept": "application/zip"}) as r:
    if int(r.headers.get("content-length", 0)) > self.max_bytes:
        raise FetchError("Repository download limit exceeded")
    chunks = []
    received = 0
    for chunk in r.iter_bytes(chunk_size=65536):
        received += len(chunk)
        if received > self.max_bytes:
            raise FetchError("Repository download limit exceeded")
        chunks.append(chunk)
    return b"".join(chunks)
F-03 Medium Redirect Location header is not enforced to use HTTPS
Description

The redirect validation in _follow_redirects_to_zip checks only the hostname against the allowlist. A Location header of http://codeload.github.com/... (plain HTTP) would pass the host check and be followed, downgrading the connection and opening the download to network interception or MitM between the server and GitHub's CDN.

Recommendation

Add a scheme check alongside the host check:

parsed_loc = urlparse(loc)
if parsed_loc.scheme.lower() != "https":
    raise FetchError("Unsafe redirect rejected")
host = (parsed_loc.hostname or "").lower()
if host not in _ALLOWED_REDIRECT_HOSTS:
    raise FetchError("Unsafe redirect rejected")
F-04 Low _resolve_default_branch uses follow_redirects=True
Description

The GitHub REST API call at line 30 sets follow_redirects=True, delegating all redirect logic to httpx with no host restrictions. While the URL is hardcoded to api.github.com, the GitHub API does not redirect in normal operation; the flag is unnecessary and adds surface area if GitHub were ever to issue a redirect to an unexpected host (e.g., during an incident or domain migration).

Recommendation

Set follow_redirects=False. If GitHub API ever issues a 301/302, fail fast and let the caller fall back to "main", which already happens in the except httpx.HTTPError block.

F-05 Low Validator does not block all loopback/private IP representations
Description

_BLOCKED_HOSTS in url_validation.py is a string-literal blocklist. The ip_address() path does catch private/loopback IPs numerically, but only when the input parses as an IP. Hostnames like github.com are pinned separately. The combination is correct in the current narrow context (only github.com is allowed). However, _BLOCKED_HOSTS is dead code: the hostname check on line 27 (host != "github.com") already rejects everything else before the blocklist is consulted on line 29, so the blocklist provides no actual protection.

Recommendation

Remove _BLOCKED_HOSTS and the dead-code check on line 29 to avoid creating a false sense of defence-in-depth. The hostname equality check is sufficient and clear on its own. Alternatively, move the IP-based private/loopback check before the hostname equality guard if you want it as a true belt-and-suspenders layer.

F-06 Info No read timeout on the streaming body download
Description

httpx.Client(timeout=self.timeout) applies the same timeout value to the connect phase and the full response read. httpx's default Timeout object treats a single scalar as a "total" timeout, but if the server begins sending data very slowly, the connection may remain open for the full timeout seconds even while delivering almost nothing. For a 30-second timeout and a server trickling bytes, this is a slow-read resource exhaustion vector.

Recommendation

Use an explicit per-phase timeout with a short read timeout:

timeout = httpx.Timeout(connect=10.0, read=30.0, write=5.0, pool=5.0)
F-07 Info Branch name from API response is interpolated into a URL without sanitisation
Description

The string returned by _resolve_default_branch is used directly in an f-string URL on line 56: f"https://github.com/.../refs/heads/{branch}.zip". Because this URL is then only processed by _follow_redirects_to_zip, whose host-allowlist validates the destination after any redirect, an unusual branch name (e.g., containing ../ or URL-special characters) could produce a malformed URL or unexpected path traversal at GitHub's CDN. The practical risk is low because GitHub's own API controls the branch name value, but the code assumes that value is safe without verifying it.

Recommendation

Validate the branch name against a safe pattern before interpolation:

import re
_BRANCH_RE = re.compile(r"^[A-Za-z0-9._/\-]{1,255}$")
if not _BRANCH_RE.match(branch):
    raise FetchError("Unexpected branch name format")

Recommended Fix Priority

  1. F-03 — Add HTTPS scheme enforcement on redirect Location values (one-liner, high leverage).
  2. F-02 — Switch to streaming download with incremental size check (prevents OOM under adversarial CDN responses).
  3. F-01 / F-04 — Disable follow_redirects on the API call and assert the target host (belt-and-suspenders for the TOCTOU surface).
  4. F-06 — Use a structured per-phase httpx.Timeout.
  5. F-05 — Remove dead _BLOCKED_HOSTS code to reduce misleading defence-in-depth illusion.
